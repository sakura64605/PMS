# 2026-10-23 待审宠物详情及编辑送审修复

## 用户反馈与原因

1. 待审核领养/救助点击查看时不能打开，同时发出 pet 和 activity 请求：宠物详情页面在失败后按同 ID 试活动接口；后端又一律拒绝待审内容，连作者/管理员也不允许；详情 DTO 缺少页面判断审核按钮所需的 auditStatus。
2. 已审核帖子编辑后再次通过/拒绝报“待审核记录不存在或已处理”：编辑只把内容 audit_status 重置为 0，没有创建下一轮审核记录，内容读模型与审批写模型不一致。

## 修复（业务代码 e3ff06e）

- 宠物页面只请求宠物接口，成功、业务失败、网络失败均不尝试活动接口。
- 详情响应追加 auditStatus；作者和管理员可预览待审/拒审内容，非公开预览不进入共享缓存、不增加浏览数。读取共享缓存前检查数据库当前可见性，防止编辑后的旧公开缓存泄露待审内容。
- 编辑先锁宠物行，再在同一事务中重置审核状态并通过 AuditCommandService.ensurePending 创建或复用唯一待审记录。保留旧通过/拒绝历史；重复待审记录不静默合并而是拒绝并整体回滚。
- 保留原审批的条件更新、目标锁与重复审批拒绝，不靠移除状态校验绕过问题。
- 旧等价性测试中“作者也不能看待审”的断言改为非作者拒绝；作者/管理员新行为另有明确测试，未运行会全表灌种子的等价性库测试。
