# 架构决策记录（ADR）

> 这些记录保留决策发生时的背景。最终落地情况见 [大规模重构前后对比报告](../refactoring/full-refactor-comparison-20261027.md)：0005 的 Outbox 尚未形成完整可靠投递闭环，0006 的“删目录即回滚”仅适用于初期并存阶段，当前需按版本产物和配置协调回滚。

记录本次后端重构中每一个「值得解释为什么」的决定。

每条 ADR 的结构是固定的四段：**背景**（为什么需要做决定）、**可选方案**、
**决定**、**后果**（收益与代价，代价要诚实写）。面试时被追问，
能说清"我考虑过 X，最后没选它是由于 Y"比只说"我用了策略模式"有价值得多。
