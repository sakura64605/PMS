# 私信模块重构

## 接管和兼容

新实现位于 refactor.privateMessage，由 PmsPrivateMessageServiceImpl 通过 @Primary 实现原 PrivateMessageService，接管原 Controller 的全部入口。原接口路径 /pet-system/message/private 下的 send、conversations、messages、unread-count、read/{conversationId}、conversation 和删除路径均保留。旧 Controller、Service、实体及 DTO 不删除，无表结构变更。

新查询直接读取数据库，不复用旧聊天记录/会话缓存。旧实现先取不含访问者身份的聊天缓存，再检查归属，存在权限绕过与双方删除视图混淆风险；新入口首先验证登录上下文与 actor 参数一致，并对会话相关读取、已读、清空、删除逐一验证参与者身份，之后才读写消息。不引入新的 Redis 依赖，也不自动清理全局 Redis 数据；旧缓存会按原 TTL 到期。

发送校验接收者正数 ID、禁止给自己发送、内容非空且最多 1000 个 Unicode 字符，以及消息类型仅文本 1/图片 2。空类型沿用默认文本。禁用或不存在的用户不能新建会话或发送。旧记录读取不额外禁止参与者访问。

## 模型与事务

PrivateMessageWriteMapper 集中当前读、条件更新、批量软删除和私有读模型 SQL。ConversationView 是访问者视角的会话投影，PrivateMessageSql 复用按发送方/接收方删除标记判断可见性的规则，避免用共享 last_message 代表双方各自的状态。

会话创建及发送按用户 ID 从小到大锁用户行，再按规范化 user_a/user_b 查找并锁定会话；不存在时创建。既有唯一键 uk_users 为最后一道约束。读取并标已读、清空和删除先锁会话行；发送持有同一会话锁后插入消息、更新共享预览和未读计数，避免已读竞争使计数丢失。用户锁沿用关注模块的升序约定，但此保证仅覆盖新入口，不能约束直接 SQL 或旧代码绕过协议的写入。

发送事务原子覆盖会话创建、消息插入、预览和未读计数。正文保留最多 1000 字符，500 字符的共享预览按 Unicode 字符边界截断，避免合法长消息因为旧会话预览列较短而失败。消息时间、删除标记与初始已读状态显式设置，不依赖测试/生产自动填充差异。

消息列表保留创建时间升序，并用 ID 作为同时间排序依据。列表调用继续沿用“打开会话即标该会话所有当前可见收到消息已读”的语义，不只标某页；相关更新和分页读取共用事务，可回滚。分页使用公共 PageQuery，每页默认 20、最多 100，总数保留。每页发送者/对方资料一次批量加载，避免逐条查用户。

会话列表的预览、时间与未读数根据访问者可见消息计算；总未读也根据实际未读且接收方未删除的消息计算，并校验所属会话参与者，避免旧冗余计数漂移影响响应。新写仍维护既有会话计数供其他旧代码兼容，不进行全库历史修复。列表使用 REPEATABLE_READ 事务保证其分页统计和装配的快照一致性。

## 删除与推送边界

清空和删除会话均只设置当前用户对应的消息删除标记、清除自己的未读数，不改变对方删除标记，不覆盖共享预览，也不物理删除会话。双方看到各自可见的预览，单方清空后对方历史和预览保留；后续新消息可继续到达。

现有表没有参与者级“隐藏整个会话”字段，因此本轮删除不会从会话列表彻底隐藏容器，清空后的会话可显示空预览；“清空保留容器”和“删除隐藏容器”的持久化区别仍需后续参与者状态模型。两侧都清空后也保留容器，避免旧逻辑误删共享会话、产生孤立消息和不可访问的对方历史。没有引入物理历史清理策略。

PrivateMessageCommitted 是事务内产生的事实，@TransactionalEventListener 提交后通过 PrivateMessagePush 适配旧静态 WebSocket 传输；失败记录消息 ID 和接收者，不记录私信正文，不回滚已提交消息。没有 outbox、自动重试或离线推送保证；数据库消息仍可在后续会话查询读取。WebSocket 服务自身的认证和会话管理不在本轮范围。

## 验证及回退

9 项单元测试覆盖身份伪造、匿名访问、越权读写、自发消息、类型和长度校验、删除只影响本人标记、插入失败不发布事件。

PrivateMessageMySqlTest 显式设置 PMS_PRIVATE_MYSQL_TESTS 后，只允许本机 3306 的 pet_system_test，验证库名和三张写表均为 InnoDB。使用随机标记用户和消息，只清理自身会话/消息/用户并确认用户移除，无共享种子或改表。10 项场景覆盖并发反向发送、并发建会话、发送与已读竞争、单方删除及后续消息、所有会话入口越权拦截、外层回滚、独立连接确认提交后推送、推送异常隔离、长正文/短预览及 Controller 主服务接管和分页。

2026-10-23 验证结果：私信 19 项专项测试全部通过，其中 10 项为本机 MySQL 集成场景。关闭数据库测试并排除原有依赖外部服务的 PmsApplicationTests 后，整体回归 251 项中 213 项通过、38 项显式跳过，无失败；数据库专项按上述独立运行，不以跳过代替验证。

这些测试使用真实 MySQL 事务及 Mapper，WebSocket 传输使用 mock；完整应用启动和实际客户端推送未在本轮验证。会话读模型的相关子查询和深分页需要在真实数据规模评估索引与性能，本轮不宣称通过负载测试。

回退需排除整个 refactor.privateMessage 的组件及 Mapper 扫描，恢复旧 PrivateMessageServiceImpl 注入；回退前应按需要失效旧 conversation/message 命名空间缓存，避免读到此前遗留视图。只移除 @Primary 会导致双实现注入歧义。本轮未改表，无反向表迁移要求。
