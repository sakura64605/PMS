# AI 会话、消息与人工转接重构

## 范围与兼容

新增 refactor/ai，接管 ChatSessionService、ChatMemoryService、HumanTransferService，
三个兼容适配器使用 @Primary 并覆盖各旧类全部公开业务方法。
旧服务实现、原实体/DTO/表结构均保留，不新增数据库列或表。
HTTP 路径、请求字段、响应结构和页面按钮位置不变。
共享 REST/WS 适配层改用统一会话网关，不改模型引擎、提示词、工具和长期记忆逻辑。

## 职责与设计

- AiConversationGateway：REST/WS 共用的身份绑定、消息校验、会话准备与模型入口。
- AiSessions：会话创建、列表、归属、历史、软删除、缓存清理和反馈。
- AiTransfers：请求、接单、关闭转人工的状态流转与事务。
- AiMessageWriter：独立消息写入事务，同时维护会话计数和更新时间。
- AiTurnContext：请求线程内关联已持久化的助手消息 ID 与模型响应，finally 清理。
- AiSessionCache：旧 Redis 短期记忆键的清理及提交后失效。
- AiSessionState / AiTransferState：显式状态含义。
- PmsChatSessionService / PmsChatMemoryService / PmsHumanTransferService：旧调用契约适配。

使用窄职责服务、门面/适配器、状态枚举及提交后副作用；
不为套用模式而把三种业务抽象成通用 CRUD 基类。

## 归属和消息入口

网关的 actor 来自 HTTP UserContext 或每次 WS 消息重新认证的身份，
不采信请求体 userId。创建新会话前校验消息非空且不超过 8000 字符。
已有会话必须归属当前用户且未删除；人工处理中拒绝继续提交 AI 对话。

历史、反馈、清缓存、转人工、删除均在新入口检查归属。
不存在、已删除或不属于本人均不暴露会话内容。
历史控制器保留原来对非本人会话返回空列表的外部行为；
直接服务调用拒绝访问。转人工会话仍出现在本人的历史列表中。

WS 不再把传输连接 ID 当作数据库 session_id。
每个连接绑定真实业务会话，可在重连时显式携带本人已有 sessionId；
同连接首次绑定通过并发 Map 原子完成，连接关闭清理绑定。
对外响应返回数据库会话 ID。旧 WS 无会话归属记录的孤立历史不自动认领。

模型及工具网络调用不处于数据库事务中。
同一会话的多个模型回合尚未串行化，仍可能并发推理；
本批保证消息数据库写入串行和不同请求消息 ID 隔离，不承诺整轮推理顺序。

## 消息、计数与反馈

新消息写入单独事务，先锁所属会话，再插入消息，并原子加 message_count、更新 updated_at。
任一步数据库失败全部回滚，不提前推送 Redis 消息。
消息提交后清理旧缓存；Redis 失效失败记录日志，不丢弃已提交消息。
近期上下文直接从数据库读取，不把旧 Redis 列表作为权威来源，
按 created_at、id 确定顺序；最多 100 轮/200 条，0 轮返回空列表。

修复旧引擎“响应 messageId 与落库 messageId 不同”的关联问题：
消息适配器记录真实助手消息 ID，网关返回该 ID，使即时反馈能更新到对应记录。
不同线程的回合上下文隔离，成功或异常都清理线程状态。
没有成功落库助手回复的故障响应仍可能只有引擎临时 ID，不伪造已保存记录。

反馈只接受本人的、唯一匹配的 assistant 消息，分数仅 0/1（对齐当前前端）。
用户消息、非法分数、重复历史 message_id 等不会被批量误更新。
历史 message_count 不回填校准；本批仅对新提交消息正确递增。
历史消息和软删除数据不做批量迁移或清除。

## 转人工、删除及并发

会话状态为删除 0、AI 活跃 1、人工处理中 3；
转接状态为待接单 1、已接单 2、已关闭 3。

所有转接变更采用“会话行，再转接行”的锁顺序：
- 同会话重复请求只保留一条未完成转接。
- 会话状态与转接记录同一事务提交，失败不留孤立转接记录。
- 接单要求当前管理员身份，adminId 必须与当前身份一致。
- 已接单的转接只允许接单管理员关闭；关闭后仅将人工处理中会话恢复为活跃。
- 删除在会话锁内关闭未完成转接并软删除会话，提交后清缓存。
- 关闭转接与删除并发，不能使已删除会话恢复。
- 消息写入也锁同一会话；删除先完成则后续写入被拒绝。
  写入先完成则作为历史保留，之后的软删除依然使会话不可访问。

删除不取消已发出的模型/工具网络请求；只拦截之后的落库，
也不是物理擦除历史数据的功能。

## 清缓存的既有语义

clearMemory 仍是清理短期 Redis 缓存，保留数据库历史。
清理失败返回错误，不报告为清理成功。
近期上下文会从数据库读取，因此该操作不等价于“让模型忘记数据库中的旧对话”。
真正的上下文重置边界与长期记忆重构留到下一批，不在本批偷偷改变现有数据结构。
长期记忆、清缓存、转人工按钮的位置未改。
