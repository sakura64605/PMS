# 业务迁移收尾（2026-10-25）

## 本次边界

按用户确认，迁移仍在运行的业务实现，保留共享实体、Mapper、DTO、接口契约及公共基础设施。HTTP 请求路径保持不变。没有删除旧 DTO 或旧业务源码，也没有更改生产部署。

## 已完成

- 12 个原来继承旧具体 Service 的新门面改为实现 refactor 下的服务接口。移除旧父类构造依赖，控制器、监听器、任务和 AI 调用方改用新接口。
- AI 引擎、模型装配、token 统计、长期记忆及抽取、RAG、向量访问、工具及注册表迁到 refactor.ai。保留既有算法和对外契约；工具注册增加重名启动失败检查。
- 审核详情及缓存策略迁到 refactor.audit.handler；活动状态任务、Feed 清理、处罚规则、数据库任务写入和宠物分类规则迁到对应新模块。
- 分类管理控制器只保留 HTTP 适配，CRUD 和权限规则委托 PetCategories；知识库分页查询委托新的 KnowledgeBaseService。
- 站内通知 MQ 消费实现迁到 refactor.message.messaging，原生产者基础设施继续复用。
- 旧延迟消息消费者改由新适配器接收，并转换为数据库任务，由现有 XXL-JOB 任务链执行。按活动行锁串行处理重投，使用当前活动时间，已有待处理或已完成同时间任务不会重复插入；异常交给 MQ 重试。
- 被替代的旧业务 Bean 增加 legacy-reference profile，默认及本地/生产配置不注册。旧源码仅供比较和指定测试切片使用；该 profile 不是整套应用的自动回滚开关。

## 清理边界与遗留功能

不能直接清空 modules、AI、common：其中还包含使用中的控制器、WebSocket 适配器、实体、Mapper、DTO、事件、共享接口和基础设施。旧新等价性测试仍显式实例化部分旧类；物理清理这些类应同时处理基线测试。

本次迁移保留既有行为，并未顺带实现原有空接口或改变产品功能：评论删除空实现、搜索建议空列表、清除会话缓存与长期遗忘的区别，以及默认未开启的 outbox 派发仍应单独处理。分类 ID 分配及品种关键词维持原规则，本次不宣称解决字典并发分配或全面数据驱动分类。
