# AI 会话短期上下文

原实现只注入最近 N 轮，窗口外信息丢失。现在在当前消息落库前生成请求独享上下文，避免本轮用户问题重复注入。

- 默认保留最近 5 个用户轮次的原文（可由 ai.agent.max-memory-rounds 覆盖），不是简单截取 10 条消息。
- 更早历史按 ID 升序、每批最多 12000 字符交给现有 ChatModel 压缩，滚动合并摘要，最终最多 2000 字符。保留宠物身份、症状时间线、约束、已执行操作及待解决问题；区分用户陈述与助手建议。
- Redis 摘要检查点以会话 ID、累计历史内容 SHA-256 及压缩参数隔离，TTL 24 小时。相同历史前缀复用摘要，变化后的片段重新压缩；缓存失败不影响原文窗口，模型失败则本请求仅使用最近窗口，不写无效摘要。
- 摘要作为明确标注的历史资料注入，不覆盖系统提示词，不注册新工具，不写入跨会话长期记忆；原始聊天记录不改写。
- enable-memory=false 不读取上下文；enable-context-compression=false 仅保留原文窗口。
- 可调项：ai.agent.memory-summary-max-chars、ai.agent.memory-compression-batch-chars，分别默认 2000、12000。字符上限不是 token 上限。

## 验证与边界

相关测试 29 项通过，覆盖窗口与摘要分离、压缩故障回退、禁用记忆，以及现有会话/工具行为。模型调用使用 mock，未验证真实模型的提炼质量。

本版按会话读取历史后划分窗口，首次压缩长会话会增加响应时间和模型费用；后续复用完整批次缓存，尾批变化时重新压缩。缓存丢失可从原始记录重建。摘要为有损压缩，不能替代原始聊天记录或保证事实永不丢失。Redis 检查点自然过期，不改变原有“清除记忆”接口语义；该接口当前只清缓存，不删除数据库聊天历史，后续请求仍可能从历史恢复上下文。

未修改数据库结构、HTTP 接口或前端，未部署。
