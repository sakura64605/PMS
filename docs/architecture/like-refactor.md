# 点赞模块重构

代码位于 `refactor/like`，实现原有 `LikeService`，通过 `@Primary` 接管。旧实现、Controller、DTO 和数据库表均保留，HTTP 路径不变。

## 结构

- `LikeTarget`：读取目标快照、增减计数的策略端口。
- `LikeTargets`：分别注册帖子、活动、评论策略，复用现有 Mapper；策略注册表检测重复键。
- `PmsLikeServiceImpl`：登录与参数校验、记录切换、计数更新、事件发布。
- `LikeChangedListener`：事务提交后通知，以及活动详情、列表、报名列表缓存失效。

策略以已有字符串 `pet_post` / `pet_activity` / `pet_comment` 为键。暂不扩展类型别名，避免把历史记录重复写成另一种类型。

## 一致性边界

点赞记录和计数在同一数据库事务内更新。先写入记录，再增加计数；唯一索引拒绝重复写入时不会先修改计数。取消操作检查删除行数，避免同一条记录被并发取消时重复减数。

返回计数保持基于操作前快照计算的接口语义，并将下限限制为零；它不是所有并发用户操作完成后的强一致总数。

通知、Redis 操作由 AFTER_COMMIT 监听器执行。当前是进程内事件，没有持久化重放：提交后进程退出可能丢失副作用。后续应在发件箱重放链路实现并验证后统一迁移，不能把当前方案表述为可靠投递。

## 验证与上线

新增测试覆盖创建记录与计数更新顺序、记录写入失败、并发取消、非法类型、匿名请求、自赞不通知、取消不通知、活动缓存区域兼容。

本轮仅修改本地代码，未部署服务器，未切换物理表。数据库及真实 MQ/Redis 的端到端验证仍需后续完成。

## 本轮执行结果与已有缺口

2026-10-19：新增 9 个点赞测试通过；不带数据库配置的重构回归共 126 个用例通过。数据库等价性测试因未配置环境变量未执行。

回归同时暴露旧公告实现的生命周期问题：即使新实现标记 `@Primary`，旧 `NoticeServiceImpl` 的 `@PostConstruct` 依然执行。装配测试使用 Mock Redis，旧后台线程因此抛出 NPE，但 Surefire 未把它计入失败。正式运行时旧消费者也不会因 `@Primary` 自动停用。必须在后续生命周期切换中显式关闭旧消费者，并验证回退路径；当前不能宣称旧实现已完全停用。

2026-10-19 后续修复：旧公告 Service 已改用 SmartLifecycle，并在启动前核对当前接口候选。
新实现接管时旧消费者不会启动；旧实现独立运行时仍可消费 Redis 队列，并在关闭时退出。
对应专项测试已通过。该修复尚未部署到服务器，不能据此认定服务器上的旧线程已停止。
