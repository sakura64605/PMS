# 日常动态、话题与推荐重构

## 范围与兼容
日常发布、详情、删除、点赞、推荐流、行为记录、热门/搜索/创建话题均已接入新实现。
保留原表、实体、DTO、HTTP路径、旧服务及旧推荐辅助类。
旧服务是具体类而非接口，因此使用 @Primary 兼容适配器覆盖所有公开方法，
让原有 DailyPostService、DailyRecommendService、DailyUserInterestService、TopicService 注入点接到新实现。
旧 Recall/Rank 辅助类仅为旧构造器兼容保留，新推荐不再调用它们。

## 分层与设计
- DailyCommands：发布、删除的事务命令。
- DailyQueries：详情可见性及浏览数。
- DailyAssembler：批量作者、话题、点赞、关注装配。
- DailyLikeTarget：注册到统一点赞策略，复用既有并发安全写入流程。
- DailyInterest：行为日志与兴趣画像在数据库中同步提交。
- DailyRecallSource / DailyRecallConfiguration：兴趣、关注、热门、新鲜四种召回策略。
- DailyRecommendation：候选去重、可见性检查、批量排序和分页。
- DailyChanged / DailyChangedListener：提交后清理旧缓存并按ID同步搜索。
- PmsTopicService：规范话题名、处理唯一键竞争、限制查询数量。

## 行为修复
发布不再直接持久化客户端实体；仅复制正文、媒体、位置和话题。
ID、作者、状态、审核标记、计数、创建时间均由服务端设置。
允许纯图片/视频；空内容、非法/停用话题、有效禁言及禁用账号会被拒绝。
话题ID去重并按固定顺序加锁，关联与计数、待审记录随帖子一起提交。

公开详情、推荐、点赞和行为记录均要求未删除且审核通过。
组织者与管理员可预览未删除的待审/拒绝内容；预览不计浏览。
浏览数原子增加，响应返回增加后的数值。
日常点赞保留 Boolean 响应及“不发送点赞通知”的既有行为。

删除在帖子行锁内仅写删除状态，不覆盖其他计数；解绑话题并减计数一次。
只撤回未决审核记录，保留已完成审核历史。
审核写入也要求帖子仍未删除，删除和审核并发时不会使内容重新出现。
修正新日常拒绝审核的状态语义：拒绝只改 audit_status，不把 status 改为删除，
使“拒绝”与“作者删除”分开。历史已存 status=0 的拒绝记录保持原样、不批量修复。

话题创建先统一前后井号和空白，再检查唯一键；并发重复创建返回业务错误。
热门与搜索仅返回启用话题，数量限制在1至50。
话题 post_count 的增减对应未删除关联数量，本批不校准历史遗留计数。

## 推荐与画像
推荐保留兴趣0.4、热度0.3、新鲜度0.2、关注0.1的排序结构。
各召回最多100条，候选按帖子ID去重，排序前再读当前审核与删除状态。
排序话题批量读取，分数相同按ID排序，不再逐条查询话题。
分页最高100条，超出候选范围返回空页；total 是可见候选数量，并非全库帖子总数。
返回DTO逐次装配，避免缓存页长期携带旧点赞、关注、作者资料或计数。
旧 Redis 推荐页仍通过既有失效器清理，新实现不再写入这些DTO页。

行为只接受 view/like/share/follow，校验当前用户及公开目标。
固定先锁帖子再锁用户，串行合并该用户兴趣JSON，行为记录和画像同事务写入；
不再使用无事务的异步Redis→MySQL覆盖流程。MySQL画像是新实现的读取来源。
画像解析忽略非数值/非有限值，对损坏JSON回退空画像；旧Redis兴趣缓存不再作为权威来源。
