# 私信历史游标与上滑加载

接口路径仍为 `GET /pet-system/message/private/messages`。

- 首次请求：`conversationId=...&pageSize=30`，取最近消息。
- 更早历史：传上批返回的 `nextCursor` 为 `beforeId`，只查询 `id < beforeId`。
- 新消息增量：`afterId` 查询 `id > afterId`；不能与 `beforeId` 同传。
- `pageSize` 限制 1–100，默认 30。返回 `records`、`nextCursor`、`hasMore`，不再计算总数或 OFFSET。

历史响应按 ID 降序，`nextCursor` 就是最后一条记录的 ID；新消息增量按 ID 升序。SQL 多取一条判断 `hasMore`。边界排他，游标消息被删除后仍可继续；可见性筛选和会话成员校验保留。原分页 DTO / Java 方法保留兼容内部旧调用，公开聊天历史入口已改为游标。

聊天窗口初始定位到底部，接近顶部时自动加载历史，合并去重后补偿 scrollTop。发送消息直接追加，推送通知 / 可见页面定时检查用独立的已同步 ID 获取增量，避免发送回包导致遗漏中间消息。阅读旧消息时收到新消息不强制滚到底部；主动发送则定位新消息。切换联系人、清空历史和卸载会废弃旧请求。

索引用于 `(conversation_id, id)` 范围查询；新环境部署前可执行 `database/manual/20261026-private-message-cursor-index.sql`，先检查有无等价索引。2026-10-26 已按用户授权添加线上索引并同步发布前后端，详见[发布记录](../deployment/private-message-cursor-20261026.md)。

## 消息时间展示

第一条消息、与前一条间隔至少 5 分钟、或跨天时，在消息组之间独立居中显示时间，分隔不属于任何气泡。今天只显示时分，昨天显示“昨天”，其他日期显示月日，跨年显示年份。每条气泡用原生悬停提示显示精确到秒的时间，不常驻显示时间。按北京时间解释后端无时区的 LocalDateTime；上滑合并历史后重新计算相邻分隔，避免分页边界产生重复标签。时间展示与新消息提示已于 2026-10-26 随前端版本 `2b4ba58` 发布。

## 重连补消息与发送重试

通知连接使用有上限的指数退避（2 / 4 / 8 / 16 / 30 秒），不再在五次失败后永久停止。15 秒未完成的握手会关闭后重建；退出登录 / 卸载取消重连。连接成功、浏览器恢复联网或页面重新可见时，聊天记录用最后确认的 `afterId` 立即补查；同一时间只进行一轮同步，期间发生的恢复事件会排队补查一次。超过一轮的积压分批继续读取，失败不前移游标、不清空已有历史，并显示“重试同步”。原有可见页面轮询继续保留。

发送中不提前清空输入；失败显示待重试内容，按账号和会话隔离草稿 / 失败项。重试绑定原接收者、原正文和原 `clientMessageId`；发送期间修改的新草稿不会被旧回执覆盖。状态保存在当前私信窗口的内存中，不写入浏览器长期存储。如果历史补查发现同一客户端标识的已提交消息，会自动确认失败项，而不再次发送或强制改变阅读位置。

服务端新增可选 `clientMessageId`（16–64 位 ASCII 字母、数字、下划线或横线），旧客户端可以不传。`private_message` 增加可空字段和唯一约束 `(from_user_id, client_message_id)`；重试在既有事务与用户 / 会话锁内返回原消息，不重复写入、增加未读或推送。同一标识换正文 / 接收者会被拒绝，已被发送者清空的消息不能通过重试重新出现。不同发送者可以使用相同标识，事务回滚不会占用标识。

发布顺序：先检查并执行 `database/manual/20261026-private-message-client-id.sql`，再更新后端，最后发布前端。2026-10-26 已按用户授权添加线上字段与唯一索引，并完成真实重试及断线补查验证，详见[发布记录](../deployment/private-message-reliability-20261026.md)。
