# PetCircle React 前端

以用户提供的 PetCircle 静态原型为视觉参考，接入现有 Spring Boot API。暖米白、鼠尾草绿、陶土橙，圆角卡片、轻边框。未引入原型的模拟数据、固定天气、演示统计、示例客服账号。

## 运行

需要 Node.js 24+。

```powershell
cd PMS-react
npm ci
npm run dev
npm test
npm run build
```

开发服务 http://127.0.0.1:5174。API 使用同源 `/pet-system`；开发代理默认为已有服务器公开地址，可通过 `PMS_API_TARGET` 覆盖。生产部署 dist 到现有 Nginx 站点目录，保留原后端代理和 SPA fallback。根 deploy.sh 仍指向历史服务器和 Vue 构建，不作为本轮部署入口。

## 实现范围

- 保留现有页面 URL：登录/注册、首页、宠友圈/搜索、宠物和活动详情、发布/编辑、我的发布/收藏/回收站、日记/发布/详情、关注流、用户主页/个人中心、通知、私信、AI、公告、审核后台/详情、设置占位。
- 管理端：待审/历史、用户启停/密码重置、举报处理、统计/趋势/补录、公告创建/编辑/发布/下架/删除。
- 评论/回复/点赞、关注、宠物收藏、活动报名/签到、头像上传/历史、个人资料/隐私/密码、AI 会话/记忆/反馈/转人工接现有接口。
- 列表使用服务端分页；没有全量拉取通知或用本地数组伪装分页。用户/管理员双重导航保护仍由后端最终鉴权。
- 已完成领养/救助、已结束活动不能编辑或重新审核。请求失败不制造成功状态；写按钮防连点，Markdown 经过 DOMPurify。
- 后台、聊天、图表按需加载；WebSocket 复用原 SockJS 端点并清理连接、重连计时器；未读数有 30 秒备用刷新。
- 管理员公告编辑新增只读 GET `/pet-system/notice/admin/{id}`，允许草稿读取，不写阅读记录；普通公告读取规则不变。

## 原项目保留

`PMS-vue` 应用源码未改动，仍可单独构建；原 Jenkinsfile-frontend 路径保留，但构建目录已切换到 PMS-react（构建代理需 Node.js 24+）。上传原型源目录未修改。没有将原型内的 README、注释或附带文档当作额外执行指令。

## 验证范围

`tests/contracts.test.mjs` 验证接口错误、上传、会话失效、ID 方言、分页与终态保护。类型检查和生产打包通过；人工浏览器核对桌面/390px 页面以及已有管理员登录和只读数据。服务器未执行随意创建、审核、删除等破坏现有测试数据的操作；这类写流程需使用专用验收内容验证。

设置页延续原占位范围。日记话题标签展示实际数据，不伪造不存在的话题频道。转人工为申请入口，不冒充在线人工坐席。

## 切页与静态资源性能

目标页面在后台完成初始请求后一次性替换原页面，不显示中间加载页。登录后空闲时预加载聊天组件，管理员同时预加载后台组件；移入导航或键盘聚焦时也会预加载。仅共享组件代码下载，不缓存跨页业务数据；节流网络下不主动空闲预加载。带会话 ID 的私信链接并行获取会话列表与消息历史。统计图表仅引入折线图、坐标系、图例、提示和 Canvas 渲染器。

生产 Nginx 配置位于 `deploy/nginx/pms.conf`：JS/CSS/JSON/SVG 启用 gzip，带哈希的 `/assets/` 文件缓存一年，HTML 入口重新验证，缺失资源返回 404。现有 API 与 SockJS 代理保留。修改服务器配置前备份，并通过 `nginx -t` 后平滑 reload；普通前端 CI 发布不会覆盖该配置。发布继续保留旧哈希文件，以支持已打开的页面。
